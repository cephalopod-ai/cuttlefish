# Cuttlefish v0.23.8 (unpublished candidate)

## A2A federation, Vibe, and restart-safe remote work

Cuttlefish v0.23.8 was prepared with bidirectional A2A Protocol 1.0 HTTP+JSON
federation, Mistral's Vibe CLI, and the security, gateway architecture,
configuration, dependency, and runtime reliability work landed after v0.23.7.
It was never tagged or published; the complete candidate is incorporated into
v0.23.9.

### Highlights

- Opt-in A2A federation exposes a filtered Agent Card, accepts authenticated
  inbound tasks, projects Cuttlefish sessions into A2A lifecycle states, and
  streams progress while preserving approvals and cancellation semantics.
- Outbound peers are explicitly configured and service-allowlisted. Exact
  origin checks, HTTPS credential transport, redirect revalidation, private
  host blocking, DNS pinning, bounded responses, and stripped caller auth
  headers confine the network boundary.
- A2A multipart inputs support text, canonical structured data, bounded raw
  files, and read-only URL references. Generated artifacts cross the boundary
  as metadata only; local paths and file bytes are not exported.
- Durable outbound checkpoints, idempotent progress messages, persisted cancel
  intent, and startup reconciliation resume known remote tasks without
  duplicating sends. Taskless replay is fail-closed unless the peer explicitly
  declares guaranteed message-ID deduplication and the card URL still matches.
- Task listing pushes owner/context pagination into SQLite and processes
  dynamically projected status filters in bounded batches.
- The Vibe engine uses `vibe-acp` over Agent Client Protocol and participates in
  the existing setup, transport, and permission behavior.
- Gateway route modules delegate lifecycle and mutation rules to focused domain
  services, and configuration validation is split into focused modules behind
  its existing public facade.
- DNS-pinned server-side fetches, hardened release workflows, patched
  `brace-expansion` overrides, chat scroll stability, and visible MCP cleanup
  warnings round out the maintenance work.

### Operator notes

- A2A is disabled unless configured. Each inbound client and outbound peer must
  have an explicit service allowlist; session-scoped agent tokens cannot call
  outbound operator endpoints.
- A2A approvals remain operator-controlled in Cuttlefish. External peers see a
  sanitized input-required prompt but cannot approve privileged actions.
- Peers that do not assert guaranteed message-ID deduplication remain
  fail-closed in an unknown-outcome restart window; operators can inspect known
  remote task IDs through the outbound task endpoints.
- Cuttlefish continues to require Node.js 24.

## Publication status

This candidate was not published to npm and has no GitHub Release or platform
archives. Use v0.23.9 or a later published version; do not attempt to install
`cuttlefish-cli@0.23.8`.
